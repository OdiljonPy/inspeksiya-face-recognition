# Принятие решения об идентичности (state machine трека) и калибровка порогов

Все пороги — `config/settings.yaml`, секция `gallery`. Логика — `src/tracker.py
_decide()`. Флаги track_enroll по умолчанию ВЫКЛЮЧЕНЫ (порядок включения — внизу).

## Состояния трека

```
НОВАЯ ДЕТЕКЦИЯ ──IoU≥track_iou──> существующий трек     иначе: новый трек
трек: COLLECTING ──> MATCHED | ENROLLED | (умер: UNKNOWN, в галерею ничего)
```

Кадр трека с уже присвоенным label (MATCHED/ENROLLED) идентичность НЕ пересматривает —
держит ID до смерти трека (track_max_misses пропусков).

## Решение для трека без label (каждый кадр)

1. **Запрос к галерее**: одиночный эмбеддинг, либо (шаг 4,
   `track_enroll.match_by_aggregate: true`) скользящее взвешенное среднее последних
   `match_agg_frames` кадров — стабильнее на мелких лицах.
2. **`score >= match_threshold` (0.50)** и margin-check пройден → MATCHED:
   label биндится к треку; чёткий фронтальный кадр может обновить фото (best-shot);
   кандидат-provisional подтверждается, если это ДРУГОЙ трек спустя
   `confirm_min_gap_seconds`.
   - **margin-check** (`match_min_margin`, 0 = выкл, ТЗ рекомендует 0.08):
     если отрыв топ-1 от ближайшего ДРУГОГО человека меньше порога — матч не
     биндится, кадр уходит в серую зону (п. 4).
3. **`score < new_id_threshold` (0.30)** и кадр прошёл гейт качества
   (`new_id_min_det_score/face_px/frontality/blur`) → кандидат в НОВЫЙ ID:
   - старый путь (флаг выкл): `new_id_confirm_frames` кадров подряд → ID из
     ОДНОГО кадра;
   - track_enroll (флаг вкл): кадры копятся в буфер с весом
     det×поза×резкость; коммит при `topk` кадрах / `max_wait_seconds` / смерти
     трека, если кадров ≥ `min_frames` И средний попарный cosine буфера ≥
     `min_consistency` (0.35 — текстуры отсеиваются). ID = взвешенное среднее
     top-K, фото = лучший кадр, статус provisional (не подтверждён за
     `provisional_ttl_days` → GC удалит вместе с событиями).
4. **Серая зона** `[new_id_threshold, match_threshold)` или margin мал →
   ближайший label только РЕПОРТИТСЯ в событие, ID не биндится и НЕ создаётся.

## Калибровка на реальных данных

1. **match/new пороги**: собрать score из событий (`events.score`).
   Свои (подтверждённые визуально) обычно > 0.55; чужие/мусор < 0.30
   (бенчмарки: eval_lfw100 — чужие max 0.30; eval_smallface @37px+компрессия —
   свои med 0.55, чужие max 0.39). Если серая зона ловит много СВОИХ — включить
   шаг 4 (агрегат поднимает score своих на ~0.14), а не опускать match_threshold.
2. **min_consistency**: если реальные люди не заводятся на обзорной камере —
   смотреть логи/eval_smallface: при ~37px p10 своих = 0.41 → 0.35 ок;
   хуже 30px — снижать до 0.30 или (правильнее) камеру у прохода.
3. **new_id_min_det_score**: реальные лица дают det ≥ 0.8 на клипах; мусор
   0.4–0.6. Поднято до 0.60; если дальние реальные лица не заводятся — 0.50.
4. **Порог дедупликации** (`dedup_gallery.py --merge-threshold`): 0.6 —
   консервативно; смотреть dry-run HTML (фото рядом) перед --apply.
5. **ГЛАВНЫЙ рычаг вне кода**: битрейт/основной RTSP-поток обзорных камер —
   компрессия+смаз роняют узнаваемость с 98% до 16% при том же размере лица
   (eval_smallface).

## Порядок включения на проде (по одному, с наблюдением)

1. `track_enroll.enabled: true` (создание ID по треку, согласованность, GC);
2. `track_enroll.match_by_aggregate: true` (матчинг по агрегату — главный
   эффект для обзорных камер: 71.5% → 100% @37px);
3. `match_min_margin: 0.08` (страховка от неразличимых кандидатов);
4. `known_faces.strict_enroll: true` (после предупреждения интеграторов).
Каждый шаг: рестарт face-recognition, наблюдение день-два, откат = вернуть флаг.
